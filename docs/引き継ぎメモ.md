### C. 技術分類（大分類/小分類）の精緻化 — Supabase 側
integration スキーマのマテビューで集計。ロジックの全体像は `docs/分類ロジック一覧.md` に完全版あり。

実施内容（SQLは `supabase/` に保存）:
1. `subcat_hierarchy_align.sql` — 小分類を親大分類に従属させ、受け皿「その他」を追加。
2. `reduce_others.sql` — 支配的IPC/頻出語を既存小分類へ割当、「その他」→「汎用・基盤技術」に改称。
3. `reduce_others_papers_v3.sql` — 論文の小分類を **OpenAlexトピック名で直接マッピング**（テキスト照合をやめ精度向上）。`_paper_base`（topics展開・約50万行）と `_paper_parent` を実体テーブル化。
4. `add_seventh_subcats.sql` — 各大分類に **7つ目の小分類**（汎用の実質受け皿。例: 通信→ネットワーク基盤・分散システム、映像→音声・オーディオ処理、ヘルスケア→臨床医学・診療研究 等）を新設し、論文トピックを割当。
5. `add_seventh_subcats_patents.sql` — 上記7つ目を **特許にも反映**（IPC中心ルール＋`tech_signals_subcat` を REFRESH）。
6. `export_taxonomy_rules.sql` — ルール一覧の抽出クエリ（ドキュメント用）。
7. `refresh_all_signals.sql` — **データ更新時の運用SQL**（マテビュー全再計算を依存順で実行）。

**分類の最終到達点:** 特許は全分野ほぼ汎用0%（通信は68.6%→0%、H04W/H04L等が第7小分類へ）。論文も全分野50%未満（多くは18〜44%）。残る「汎用・基盤技術」は各分野の主流・確立技術で、妥当な着地。

### 分類ロジックの要点（説明用）
- 大分類: 特許=IPCコード（`taxonomy_patent_class`）/ 論文=OpenAlex subfield（`paper_subfield_taxonomy`）
- 小分類: 特許=IPC＋タイトル/要約キーワード（`taxonomy_patent_keyword`: ipc/word/phrase）/ 論文=トピック名 ILIKE（`taxonomy_paper_topic_pattern`→`taxonomy_paper_topic_map`）
- 親子は独立判定・非排他・ユニーク件数カウント。どの先端テーマにも当たらないと第7「汎用・基盤技術」。

### 重要: DB上の恒久オブジェクト（削除しないこと）
- マテビュー `tech_signals_paper_subcat` は **実体テーブル `integration._paper_base` / `_paper_parent` に依存**。この2つは常設（消すとマテビューが壊れる）。更新は `refresh_all_signals.sql` で。
- `_topic_names` は不要なら削除可（どこからも参照されていない）。

## 3. よくあるハマりどころ

- **Supabase SQL Editor は約60秒でゲートウェイタイムアウト。** 重いマテビュー再作成は分割実行 or 直接接続（psql / TablePlus / DBeaver で Connection string URI）。`refresh_all_signals.sql` 末尾に手順あり。
- **Vercel が新コミットを認識しない場合:** 環境変数のシークレット参照を `vercel.json` に書かない。GitHub連携は Settings→Git で確認、Deployments から手動 Redeploy 可。
- SQL 実行時「duplicate key」→ INSERT に `ON CONFLICT DO NOTHING`。「cannot drop ... depends on」→ 依存する matview を先に DROP。
